# Gaming DNS Manager

اپلیکیشن Flutter برای جمع‌آوری، ذخیره‌سازی، تست و مدیریت فهرست DNSها در اندروید.

## امکانات

- ذخیره‌سازی محلی با SQLite و جلوگیری از رکورد تکراری
- ابزار تبدیل خودکار قالب IPv4 به IPv4-mapped IPv6 و NAT64، و بازیابی IPv4 از این دو قالب شناخته‌شده
- اعتبارسنجی آدرس‌ها و نمایش هشدار برای تبدیل‌هایی که لزوماً DNS قابل‌دسترسی ایجاد نمی‌کنند
- صفحه‌بندی فهرست برای جلوگیری از بارگذاری کل پایگاه داده در حافظه
- تعیین تعداد DNS جدید برای واردکردن از اینترنت یا فایل
- دریافت از چند منبع عمومی و نمایش تعداد منابع موفق/ناموفق
- واردکردن تدریجی TXT، CSV و JSON بدون خواندن کامل فایل در حافظه
- تست DNS با پرس‌وجوی واقعی UDP روی پورت 53 و ثبت زمان پاسخ
- تست تکی و تست DNSهای صفحهٔ جاری
- حذف انتخابی، حذف آدرس‌های نامعتبر، حذف DNSهای تست‌شدهٔ بدون پاسخ
- حذف DNSهای کندتر از آستانهٔ دلخواه برحسب میلی‌ثانیه
- حذف کل پایگاه داده و خروجی TXT
- مهاجرت یک‌بارهٔ داده‌های نسخهٔ قدیمی از SharedPreferences به SQLite

## منابع آنلاین پیش‌فرض

- https://public-dns.info/nameservers.txt
- https://github.com/blacklanternsecurity/public-dns-servers
- https://github.com/pingproxies/public-dns-directory
- https://github.com/takuya/public_dns_list

وجود IP در یک فهرست به معنی سالم بودن یا مناسب‌بودن آن برای بازی نیست. زمان پاسخ فقط پس از دریافت پاسخ معتبر DNS ثبت می‌شود. منابع عمومی ممکن است موقتاً از دسترس خارج شوند؛ برنامه در این حالت DNS ساختگی به فهرست اضافه نمی‌کند.

## تبدیل IPv4 و IPv6

از آیکون تبدیل در نوار بالای برنامه استفاده کنید. با واردکردن IPv4، برنامه دو نمایش تولید می‌کند: `::ffff:a.b.c.d` به‌صورت IPv4-mapped و `64:ff9b::hhhh:hhhh` با پیشوند NAT64 شناخته‌شده. اگر IPv6 ورودی از یکی از این دو قالب باشد، IPv4 از آن بازیابی می‌شود. برای IPv6 بومی، تبدیل یکتای عمومی به IPv4 وجود ندارد؛ برنامه عمداً IPv4 ساختگی تولید نمی‌کند. این تبدیل‌ها به‌تنهایی تضمین نمی‌کنند که آدرس تولیدشده یک DNS واقعی و قابل‌دسترسی باشد.

## ساخت APK از GitHub

1. یک مخزن جدید در GitHub بسازید.
2. فایل‌های داخل این پوشه را در ریشهٔ مخزن قرار دهید و روی شاخهٔ `main` پوش کنید.
3. به زبانهٔ **Actions** بروید و workflow با نام **Build Gaming DNS APK** را باز کنید.
4. اجرای خودکار پس از push انجام می‌شود؛ برای اجرای دستی از **Run workflow** استفاده کنید.
5. پس از موفقیت، در صفحهٔ اجرای workflow بخش **Artifacts** فایل `Gaming-DNS-Release-APK` را دانلود کنید. فایل داخل آن `app-release.apk` است.

APK خروجی فعلی با کلید debug امضا می‌شود و برای آزمایش شخصی مناسب است؛ برای انتشار در فروشگاه باید کلید release خصوصی خودتان تنظیم شود. کلید امضا یا رمز آن را در مخزن عمومی قرار ندهید.

## اتصال واقعی DNS در اندروید

سرویس اتصال از `VpnService` اندروید استفاده می‌کند و برای فعال‌سازی، اجازهٔ خود اندروید را می‌گیرد. به‌جای نمایش اتصال ساختگی، یک رابط TUN با DNS مجازی IPv4/IPv6 می‌سازد، بسته‌های DNS روی UDP/53 را به DNS انتخاب‌شده می‌فرستد و پاسخ را به درخواست‌کننده برمی‌گرداند. درخواست‌های TCP/53 نیز برای پاسخ‌های بزرگ و fallback پشتیبانی می‌شوند. سوکت‌های ارتباط با DNS اصلی با `VpnService.protect()` از حلقهٔ تونل خارج می‌شوند.

هنگام اتصال، برنامه یک پرس‌وجوی واقعی را از داخل تونل می‌فرستد و فقط در صورت دریافت پاسخ معتبر وضعیت اتصال را موفق اعلام می‌کند. قطع اتصال، رابط TUN و منابع مربوط را می‌بندد.

**دامنهٔ اثر و محدودیت‌ها:**

- این یک تونل DNS محلی است، نه VPN کامل؛ ترافیک معمول اینترنت از مسیر عادی دستگاه عبور می‌کند و IP عمومی را تغییر نمی‌دهد.
- برنامه‌هایی که DNS را با HTTPS/DoH داخل خودشان پیاده‌سازی می‌کنند ممکن است از DNS سیستم استفاده نکنند؛ در نتیجه انتخاب DNS در این برنامه بر آن درخواست‌ها الزاماً اثر نمی‌گذارد.
- تنظیم سراسری Android Private DNS در حالت Strict/hostname ممکن است با DNS انتخاب‌شده تداخل داشته باشد. برای آزمایش، Private DNS را در تنظیمات اندروید روی Automatic یا Off قرار دهید.
- برخی شبکه‌ها UDP/TCP پورت 53 را مسدود می‌کنند یا به DNSهای مشخصی اجازهٔ دسترسی می‌دهند؛ در چنین شبکه‌ای اتصال باید خطا بدهد، نه اینکه به‌دروغ موفق اعلام شود.
- ترافیک قطعه‌قطعه‌شدهٔ IP (fragmented DNS) در این نسخه بازسازی نمی‌شود؛ بیشتر پرس‌وجوهای معمول DNS از این مسیر استفاده نمی‌کنند.

## آزمایش روی گوشی واقعی

1. APK را نصب کنید و روی اتصال DNS بزنید.
2. اجازهٔ اتصال VPN را در پنجرهٔ اندروید تأیید کنید.
3. منتظر پیام «اتصال واقعی DNS برقرار شد» بمانید؛ در غیر این صورت متن خطا را بررسی کنید.
4. با مرورگر، چند دامنه را باز کنید و عملکرد را با DNSهای متفاوت مقایسه کنید.
5. هنگام اتصال، اعلان Gaming DNS باید دیده شود. برای قطع، دکمهٔ قطع اتصال را بزنید و سپس بررسی کنید اینترنت عادی برقرار است.
6. برای تست دقیق‌تر، یک DNS عمومی را انتخاب و سپس یک DNS دیگر را آزمایش کنید. تغییر سرعت بازی تضمین نمی‌شود؛ DNS بیشتر بر زمان پیدا کردن آدرس سرور اثر می‌گذارد، نه پینگ بسته‌های بازی پس از اتصال.

## ذخیره‌سازی

SQLite برای فهرست‌های بزرگ بسیار مناسب‌تر از SharedPreferences است و این نسخه برای مدیریت فهرست‌های میلیونی با صفحه‌بندی طراحی شده است. تعداد واقعی قابل ذخیره‌سازی به فضای آزاد دستگاه، سرعت ذخیره‌ساز و اندازهٔ رکوردها بستگی دارد؛ ذخیره و پیمایش میلیاردها رکورد روی تلفن همراه هدف واقع‌بینانه‌ای نیست.


## Build compatibility notes (2.2.2)

The current `file_picker` 13.x API removed the `withData` argument from `pickFiles()`. Do not add it back. The workflow generates the Android wrapper and ensures the Android Gradle Plugin is at least 8.12.1, Gradle at least 8.13, and Kotlin at least 2.2.0 for `share_plus` 13.x.

If a GitHub Actions build still fails, the run uploads `Gaming-DNS-Build-Logs` containing the verbose Gradle/Dart build log and analyzer output. The APK is uploaded as `Gaming-DNS-Release-APK` only after a successful build.


### Fix for `android/settings.gradle` not found

Recent Flutter stable templates may generate `android/settings.gradle.kts` and `android/app/build.gradle.kts` (Kotlin DSL) instead of the older Groovy `.gradle` files. The build workflow now uses `scripts/patch_android_gradle.py`, which detects either format before adjusting plugin and wrapper versions. If a build still fails, download the `Gaming-DNS-Build-Logs` artifact from the failed Actions run.
